# Activation

`package.json` declares one activation event, `onLanguageModelChatProvider:vercelAiGateway`, so VS Code loads the extension only when something asks for models from this vendor. `engines.vscode` is `^1.137.0`.

`activate()` in `src/extension.ts`, in order:

1. Creates the `Vercel AI Gateway` log output channel (`src/logger.ts`, `initializeLogger`).
2. Constructs `VercelAIAuthenticationProvider`, which registers the `vercelAiGateway` authentication provider ([[authentication]]), and starts `watchSignedInContext`, which keeps the `vercelAiGateway.signedIn` context key in step with the sessions (see Walkthrough below).
3. Constructs one `ModelsClient` and `VercelAIChatModelProvider`, passing `authProvider.getActiveSession` as the credential source and that client, and registers the provider with `vscode.lm.registerLanguageModelChatProvider("vercelAiGateway", ...)` ([[chat-provider]]). Registers the status tool `vercelAiGateway_status` with `vscode.lm.registerTool`, given the same session source and client (see Status tool below).
4. Registers the command `vercelAiGateway.manage` ("Vercel AI Gateway: Manage Authentication"), which calls `manageAuthentication()`.
5. Registers `vercelAiGateway.checkConnection` ("Check Connection") and `vercelAiGateway.showLogs` ("Show Logs").

## Diagnostics commands

Check Connection runs `runConnectionCheck` in `src/diagnostics.ts`. It reads the active session through `authProvider.getActiveSession()` (so an expiring OIDC token is refreshed first), then sends its own `GET {endpoint}/v1/models` with the configured timeout instead of going through `ModelsClient`, so the result never comes from the five minute model cache. It reports the endpoint, the session label and method, the OIDC expiry, the HTTP status, the latency, and "Chat models: N of M listed": M is the number of entries in `data` and N the ones `isChatModel` in `src/models.ts` keeps, the same filter that builds the model picker. Before this it showed M alone, which on 2026-10-28 was 498 for the public list against 320 language models in the picker, the rest being embedding, image, video, speech and other types. Test: "counts only the chat models the picker offers apart from the total" in `src/diagnostics.test.ts`. After a model list that succeeds it sends `GET {endpoint}/v1/credits` with the same token and timeout, the endpoint `getCredits` in `@ai-sdk/gateway` reads, and shows "Credits: B left, U used" from the reply's `balance` and `total_used`, passed through as the gateway sends them, so a user whose requests fail can see whether the team is out of credits. No `x-vercel-ai-gateway-team` header is sent, so the balance is the one the gateway resolves for the token; which team that is for an OIDC token is untested. A refused request, a body without both amounts or a network failure leaves the line out and logs the reason at info; it never fails the check. On 2026-10-28 the public endpoint answered a request without credentials with 401 `authentication_error`; whether an API key or an OIDC token can read the balance is untested. Tests: "reports the credit balance after the model list" and "still passes without a balance after ..." in `src/diagnostics.test.ts`. In parallel with the balance it sends the status tool's spend request (`fetchMonthSpend`, now in `src/diagnostics.ts`, described under Status tool below) and adds the same "Spend this month" line, so a user sees the month's spend without asking an agent (#249); an unreadable report leaves the line out instead of saying so, as for the balance. Tests: the "month spend in the check" cases in `src/diagnostics.test.ts`. With no session it sends nothing. The result goes to the log at info and to an information or error message with a Show Logs button. The token is only ever in the `Authorization` header; `src/diagnostics.test.ts` asserts it never reaches the message or the log.

## Status tool

`contributes.languageModelTools` declares one read-only tool, `vercelAiGateway_status` (`STATUS_TOOL_NAME` in `src/constants.ts`), referenceable in prompts as `#gatewayStatus` (#199). `StatusTool` in `src/tools.ts` returns one text part: the active session's credit balance from `fetchCredits` (the same `GET {endpoint}/v1/credits` Check Connection sends), the spend since the first of the month, and for each id in its `modelIds` input (trimmed, deduplicated, at most 20, the schema's `maxItems`) the per million token prices, the context window and the capabilities. The prices are input and output, named "not listed" when absent, then the cache read and cache write prices only when the gateway lists them, since most agent input tokens are cache reads and many models list no cache write price (#246). The capabilities are the `toolCalling`, `imageInput` and `reasoning` flags the model picker gets from `ModelsClient.getModels` ([[chat-provider]]), named as "supports ..." or "no tool calling, image input or reasoning", so an agent can pick a model that calls tools or reads images (#236); `webSearch` is left out because only a tag sets it. Its `search` input (trimmed, case insensitive) lists the chat models whose id or name contains the term before the `modelIds` lines, at most 20 under a header with the match count, so an agent can learn ids it does not know; a blank or non string `search` counts as absent (#217). The prices come from `ModelsClient.priceOf`, recorded from the last fetched model list and formatted like the model tooltip, and the model list comes from the client the chat provider uses, so a call within five minutes of a picker load sends no models request. With no session, an unreadable session, rejected credentials or a failed model list it returns the step the user should take (Manage Authentication or Check Connection) as text instead of throwing. It defines no confirmation, since it only reads.

The spend line comes from `GET {endpoint}/v1/report?start_date=<first of the month>&end_date=<today>&group_by=model`, both dates in UTC (`fetchMonthSpend` and `describeMonthSpend` in `src/diagnostics.ts`, shared with Check Connection, #233). That is the request `getSpendReport` in `@ai-sdk/gateway` 4.0.111 sends (`src/gateway-spend-report.ts`), whose rows carry `total_cost` in US dollars and an optional `request_count`. The tool sums the rows with a numeric `total_cost`, adds a request count only when some row has one, and names the three models with the highest positive cost. A non 2xx answer, a body without a `results` array or a network failure is logged at info and becomes "the gateway did not return a spend report for this session", without a Check Connection step, since a key may lack access to the report for good. Whether the gateway's days are UTC, and which keys or OIDC tokens may read the report, was not checked against the live gateway. Tests: the spend cases in `src/tools.test.ts`. The e2e suite checks it appears in `vscode.lm.tools` after the chat provider activation event; whether VS Code activates the extension for a tool call before any model request is unverified.

Show Logs calls `logger.show()`, which reveals the `Vercel AI Gateway` output channel without taking focus.

Everything is pushed onto `context.subscriptions`. `activate()` returns nothing, so the extension exposes no API to other extensions. `deactivate()` only logs.

## Manifest contributions

All in `package.json` `contributes`: the `vercelAiGateway` authentication provider (declared since SferaDev/SferaDev#558, which removed an activation warning), the `vercelAiGateway` language model chat provider, the `vercelAiGateway_status` language model tool, the manage, check connection and show logs commands, and the settings in [[configuration]]. The chat provider declares `"icon": "$(triangle-up)"`, a codicon that follows the theme colour and needs no image in the package; VS Code 1.143 added the `icon` property, whose schema says it is "shown in the chat model picker" (`resolveLanguageModelProviderIcon` in `src/vs/workbench/contrib/chat/common/languageModels.ts` on `release/1.143`), and 1.137 to 1.142 build the vendor entry from known fields and ignore it, so the `engines.vscode` floor did not move (#129). How the picker draws it was not checked in a window. `package.json` is the extension manifest, so a change to any of these changes what users see. `src/package.test.ts` checks the commands, provider ids and activation events against `activate()` and `EXTENSION_ID`.

The top level `description` is the Marketplace short description, and the README is the listing page. Both say the extension is a community extension, not made by Vercel, and the README opens with a three step quick start that links to creating a gateway key, so the listing is the sign up path (#188). They make no model count, speed or price claims; the listing changes only on the next release. The manifest also sets `pricing` to `Free` (vsce 4.0.0 already defaults to it, so the badge is unchanged; the field states it), `qna` to the issues URL in `bugs` so the Marketplace Q and A tab links there instead of collecting questions nobody reads, a white `galleryBanner` with the `light` theme to match the black triangle on white in `images/icon.png`, and search `keywords` (vsce adds `language-models` itself from the chat provider contribution). Keywords stay at 30 or fewer: vsce 4.0.0 does not enforce a cap and whether the Marketplace does was not checked, so 30 is a margin, not a known limit. "sends Marketplace questions to the issue tracker ..." in `src/package.test.ts` checks the count and the `qna` link (#190). How the banner renders on the listing was not checked. The README "Settings" section groups the settings as Connection, Privacy, Routing and Spend reporting, Privacy before Routing, each a short table with the caveats listed under it, so the listing is not one table of paragraph long cells (#192).

## Walkthrough

`contributes.walkthroughs` holds one walkthrough, `getStarted` ("Get started with Vercel AI Gateway"), which VS Code opens on the Welcome page after install (#191). Its steps, each with Markdown media under `media/walkthrough/`:

1. `getKey`: links to the AI Gateway authentication docs. Completes on `onLink` of that URL, or on the signed in context key for a user who skips the key and uses Vercel OIDC.
2. `signIn`: a button that runs `vercelAiGateway.manage`. Completes on `onContext:vercelAiGateway.signedIn`.
3. `openChat`: a button that runs `workbench.action.chat.open`. Completes on `onCommand` of that command; picking a model has no event to complete on.

The context key is set by `updateSignedInContext` in `src/auth.ts` (key name `SIGNED_IN_CONTEXT_KEY` in `src/constants.ts`): true when a stored session exists or `AI_GATEWAY_API_KEY` gives one, read without refreshing OIDC tokens. It runs on activation and after every `onDidChangeSessions` event, and a result that a later change has overtaken is dropped. The extension has no `onStartupFinished` activation event, so the key is only set once something activates it; the sign-in button does that through the implicit `onCommand` activation of a contributed command. VS Code keeps a completed step ticked on its own, so the key going false after a sign-out does not untick it. Tests: `signed in context key` in `src/auth.test.ts`, and "walks through getting a key, signing in and opening chat" and "packages the walkthrough media" in `src/package.test.ts`. How the walkthrough renders and whether each step ticks in a real window was not checked; the e2e suite does not open it.
