# Configuration

Two settings, declared in `package.json` `contributes.configuration` and read by `getConfig()` in `src/config.ts` on every call, so a change applies to the next request without a reload:

| Setting | Default | Used by |
| --- | --- | --- |
| `vercelAiGateway.endpoint` | `https://ai-gateway.vercel.sh` | model list (`{endpoint}/v1/models`) and chat (`{endpoint}/v1/ai`); `getConfig()` strips trailing slashes, so both URLs come from one normalised value. Declared `"scope": "machine"` and read as `inspect("endpoint")?.globalValue`, so only the user's own setting counts and a workspace or folder value is ignored ([[decisions/2026-10-15-endpoint-user-settings-only]]) |
| `vercelAiGateway.timeout` | `30000` ms, range 5000 to 300000 | idle limit for the model's first chunk and for each next chunk (`firstChunkMs` and `chunkMs` in the `streamText` timeout, since #8), not a cap on the whole response; also the total limit for the model list request and the Check Connection request. VS Code returns a `settings.json` value outside the manifest's type or range as is and only underlines it, so `getConfig()` clamps a number to 5000 to 300000 (`MIN_TIMEOUT_MS` and `MAX_TIMEOUT_MS`) and uses the default for anything that is not a finite number. Before that, `0` timed out every model list fetch at once and a string made `AbortSignal.timeout` in Check Connection throw |

The model list cache is keyed by API key only, so a change to `endpoint` drops it: `VercelAIChatModelProvider` listens to `workspace.onDidChangeConfiguration` and, when `vercelAiGateway.endpoint` is affected, calls `invalidateCache` and fires `onDidChangeLanguageModelChatInformation`, the same refresh a session change triggers ([[chat-provider]]). Before that, the old endpoint's models stayed in the picker for up to 5 minutes, and a failing new endpoint fell back to the old endpoint's list. A `timeout` change does not refresh anything. Test: "invalidates cache and fires model info change when the endpoint setting changes" in `src/provider.test.ts`.

Constants that are not settings live in `src/constants.ts`: the models path, the 5 minute cache TTL, a 15 minute `TOKEN_REFRESH_MARGIN` (an OIDC token counts as expired that long before it expires, `isExpired` in `src/vercel-auth.ts`), a 15 second `VERCEL_API_TIMEOUT_MS` for each `api.vercel.com` request in the OIDC flow (fixed, unlike the `timeout` setting, which covers gateway requests), and the user-facing error strings.
